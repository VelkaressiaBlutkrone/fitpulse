## 결론

다음 단계는 앱을 만드는 일이 아니다. 먼저 구별 가능한 출시 후보 이름, 합법적으로 연구 원자료를 보관·삭제할 경로, 실제 담당자와 독립 검토자를 확보한 뒤, 조건에 맞는 30명의 최근 운동 의사결정을 관찰한다.

V1은 다음 다섯 가지 판정 조건을 모두 충족할 때만 `GO`다.

1. 30명의 유효한 인터뷰·기록 관찰을 완료한다.
2. 10명 이상이 제안 노출 전에 다음 중량·반복 결정의 반복 손실을 증거와 함께 보인다.
3. 10명 이상이 보유한 회복 데이터를 최근 훈련 조정에 일관되게 사용하지 못한다.
4. 5명 이상이 고정된 범위·기간·가격·환불 조건에 대해 실제 약정 행동을 완료한다.
5. 5명 이상의 실제 내보내기 파일 또는 익명화된 기록 형식을 확보한다.

30·10·10·5·5는 외부 업계 표준이 아니라 결과를 본 뒤 기준을 낮추는 일을 막기 위한 내부 판정 규칙이다. 30명의 유효 표본을 동결한 뒤 하나라도 미달하면 현재 웨지는 `STOP`한다. 다른 문제·대상·오퍼를 시험하려면 현재 결정을 바꾸지 않고 별도 측정 계획으로 새 게이트를 시작한다.

지원 문서는 다음과 같다.

- [B-00~B-05 승인·증거 인수 방법](./fitpulse-v0-authorization-evidence-intake-guide-20260814.md): 실제 승인 원문을 Git 밖에 두고 불투명 ID만 제출·검증하는 절차
- [V0 측정 계획](./MEASURE-V0-20260814-001.md): 현재 차단 상태, V0 검색·삭제 리허설·판정 계약
- [V1 중립 연구 모집 페이지 계획](./fitpulse-v1-research-recruitment-page-plan-20260814.md): 해결책·가격을 노출하지 않고 파일럿과 본 조사 참가자를 모집하는 절차
- [V2 랜딩 수요 실험 계획](./fitpulse-v2-landing-demand-experiment-plan-20260814.md): V1 `GO` 뒤 선택된 한 웨지의 메시지·오퍼를 시험하는 차단된 초안. 현재 실행 권한 없음

## 3. 범위

### 포함

- 브랜드 후보 5개 이상에 대한 Store·웹·상표·도메인·핸들 1차 조사
- V0·V1 책임자, 승인자, 거부권자와 비용·시간 상한 배정
- Git 밖의 승인된 연구 원자료 저장소, 접근 통제, 철회·삭제 절차 검증
- 모집 스크리너, 동의문, 비유도 인터뷰·관찰 스크립트, 표준 콘셉트 카드 작성
- 파일럿 3명과 본 조사 유효 참가자 30명
- 최근 세 번의 다음 운동 목표 결정 과정과 실제 기록 관찰
- 현재 도구, 전환 거부 이유, 내보내기 형식, 회복 데이터 사용 방식 기록
- 고정된 오퍼에 대한 실제 약정·환불 행동 측정
- 사전 등록된 계수 규칙으로 V1 `GO/LOOP/STOP` 결정

브랜드 후보 5개와 파일럿 3명은 이 계획의 운영 통제다. 외부 표준이나 시장 성공 기준으로 해석하지 않는다.

- 자동 중량 추천 알고리즘, 골든 데이터셋, 안전 경계 구현
- 공개 베타, Play Console 제출, 구독 상품 출시
- 식단·소셜·챌린지·트레이너 마켓·iOS
- 의료·재활·질환 관리 사용자 모집과 치료·진단 주장
- 만 19세 미만 참가자 모집
- 최종 상표 사용 가능성에 대한 비전문가의 법률 결론

## 4. 시작 차단 필드

아래 값은 파일을 읽거나 명령으로 확인할 수 없으므로 추측하지 않는다. 전부 실제 값으로 채워지고 해당 책임자가 승인하기 전에는 참가자 모집·연락·원자료 수집·결제를 시작하지 않는다.

실제 담당자 이름·연락처·서명은 접근 통제된 승인 기록에 두고 Git에는 역할 ID와 승인 기록의 불투명 ID만 남긴다.

B-00은 자기 선언만으로 만들지 않는다. 개인 프로젝트면 계약·결제 계정과 연구 예산을 실제로 통제하는 동일인의 서명 기록으로 확인하고, 조직 프로젝트면 대표자·예산권자 또는 조직의 위임 문서로 확인한다. GitHub 저장소 소유권만으로 연구·계약 권한을 인정하지 않는다.

| ID | 필요한 실제 값 | 승인자 | 미확정 시 |
|---|---|---|---|
| B-00 | 연구 착수·예산·외부 계약을 위임할 실제 권한자와 권한 근거 | 저장소 소유가 아니라 해당 예산·계약 권한을 가진 본인 또는 조직 승인 기록 | V0 `STOP` |
| B-01 | 위임 책임자, 제품·증거 소유자, 독립 사용자 대표, 개인정보 검토자의 실제 배정 | B-00 위임권자 | V0 `STOP` |
| B-02 | 식별정보·녹취·화면 공유·내보내기 파일을 보관할 Git 외부 저장소, 접근자, 보존기간, 백업 삭제 방식 | 개인정보 검토자 | V0 `STOP` |
| B-03 | 모집 채널, 채널별 예산·사례비, 모집 담당자와 최대 모집 기간 | 경제적 후원자 후보 | V1 진입 금지 |
| B-04 | 약정 오퍼의 정확한 범위, 제공 기간, 가격, 환불 가능한 예약금, 결제 수단, 환불 조건, 별도 참가 사례비, 계약·소비자 고지·세무 처리 | 경제적 후원자와 법무·세무 검토자 | 약정 수집 금지 |
| B-05 | 한국 우선 출시 기준 상표 전문가·예산·의뢰 경로, 허용 도메인 패턴, 필수 공식 계정 플랫폼, 최소 1개 후보의 서면 예비 검토 결과 | 제품 책임자 | 출시 후보 선정 금지 |

## 5. 역할과 독립성

| 역할 코드 | 책임 | 필수 분리 규칙 |
|---|---|---|
| R-SPONSOR | 시간·비용 상한, 실제 약정 오퍼, 최종 `GO/STOP` | 수요 증거를 대신 만들거나 개인정보 거부권을 무효화하지 않음 |
| R-PRODUCT | 웨지·대상·범위 유지, 콘셉트 카드 버전 관리 | 자신의 가설을 단독 통과시키지 않음 |
| R-EVIDENCE | 모집, 동의, 원자료 연결, 근거 계보와 철회 처리 | 자신이 수집한 30건의 유일한 검토자가 되지 않음 |
| R-USER | 질문이 실제 운동 의사결정을 반영하는지 검토 | 제품 작성자의 대리 의견으로 대체하지 않음 |
| R-PRIVACY | 수집 항목, 저장소, 접근, 보존·삭제, 사고 대응 승인 | 제품 성과를 대신 판정하지 않음 |
| R-VERIFY | 프로토콜 동결, 유효성 판정, 집계 재실행, 게이트 검토 | 본 조사 30명의 주 인터뷰어를 겸하지 않음 |
| R-FINANCE | 오퍼·결제·환불·수수료와 약정 증거 정의 | 결과를 본 뒤 가격이나 통과 기준을 바꾸지 않음 |

최소 배정 기능은 `R-SPONSOR`, `R-PRODUCT/R-EVIDENCE`, `R-USER`, `R-PRIVACY` 네 석이다. V1 본 조사 전에는 별도 `R-VERIFY`를 추가한다. `R-VERIFY`는 본 조사 30명의 주 인터뷰를 수행할 수 없고, `R-USER`는 실제 대상 사용자를 대표해야 한다. 이 분리를 충족할 인력이 없으면 V1은 `STOP`이다.

| V1 비식별 집계 요약 | `docs/discovery/EVD-YYYY-NNN-problem-observation-summary.md` | 집계값, 5명 미만 소수 셀 억제값, 원자료 배치의 불투명 ID, 철회·무효화 상태. 참가자별 행 금지 |
| V0·V1 결정 | `docs/decisions/GATE-V0-YYYYMMDD-001.md`, `docs/decisions/GATE-V1-YYYYMMDD-001.md` | 승인자, 증거 ID, `GO/LOOP/STOP`, 허용·금지 다음 작업 |
| 독립 검증 결과 | `docs/verification/VERIFY-GATE-V1-YYYYMMDD.md` | 재집계 결과, 불일치, 제외·누락, 최종 판정 |

`<slug>`, `YYYY`, `NNN`, `YYYYMMDD`는 산출 시 실제 값으로 치환한다. 자리표시자가 포함된 파일을 승인본으로 표시하지 않는다.

### Git에 두지 않을 자료

- 이름, 이메일, 전화번호, SNS 계정, 모집 대화
- 서명된 동의서와 철회 요청 원문
- 녹음·영상·화면 공유와 식별 가능한 직접 인용
- 운동 메모, 건강정보 원문, 실제 내보내기 파일
- 신원과 참가자 가명 ID를 연결하는 매핑 키
- 결제 식별자, 계좌·카드·세금 관련 원문

이 자료는 B-02에서 승인한 저장소에만 둔다. Git에는 삭제 가능한 원자료 위치를 직접 노출하지 않고 불투명한 증거 ID, 변환 이력, 유효·철회 상태만 둔다.

## 8. 표본과 편향 통제

### 필수 모집 기준

1. 만 19세 이상 한국 거주자다.
2. Android 또는 Galaxy Watch를 사용한다.
3. 근력운동 경력이 6개월 이상 3년 이하다.
4. 최근 8주 기준 주 3~5회 근력운동을 수행한다.
5. 메모·스프레드시트·운동 앱에 3개월 이상의 기록을 보유한다.
6. 다음 운동의 중량·반복·세트 수를 본인이 결정한다.
7. 최근 세 번의 운동 기록을 관찰할 수 있다.
8. 질환 치료·통증 재활·의료 조언을 목적으로 참여하지 않는다.

주 3~5회 조건은 최근 8주 근력운동 세션 수를 8로 나눈 산술평균이 `3.0 이상 5.0 이하`일 때 충족한다. 반올림하지 않으며 8주 합계는 24~40회다. 상세 세트 기록은 최근 세 번만 관찰하고, 나머지 기간에는 주차별 세션 존재와 총 세션 수만 확인한다.

### 내부 표본 통제

- 파일럿 3명은 본 조사 30명과 문제·회복·약정·내보내기 어느 분자에도 포함하지 않는다. 파일럿에서 얻은 파일은 저장·익명화 절차 검증 후 반환·삭제하고, 약정 흐름은 테스트 거래 또는 즉시 전액 환불로만 확인한다.
- `MEASURE-V1`에서 모집 시작 전에 채널 코드를 유료 모집, 체육시설·코치 제휴, 공개 커뮤니티, 기존 지인·추천으로 고정하고 채널마다 고유 스크리너 링크 또는 초대 코드를 사용한다. 참가자가 여러 경로를 거쳤다면 가장 먼저 생성된 `screening_started_at`의 유효 코드 하나만 `primary_recruitment_channel_code`로 쓴다. 새 채널은 프로토콜 버전 변경 없이 추가할 수 없고 채널 원문은 Git에 쓰지 않는다.
- 본 조사에서 한 채널의 유효 참가자가 15명에 도달한 시각을 `channel_closed_at`으로 기록하고 해당 링크·코드를 닫는다. `channel_closed_at` 전에 스크리너를 시작했지만 이후 동의한 사람을 동시 등록로 정의한다. 초과하면 `consent_completed_at`이 늦은 순서로 초과분을 표본에서 제외하고 다른 채널로 대체한다.
- 주 사용 도구의 계산 단위는 상세 관찰한 **최근 세 번의 운동 세션**이다. 각 세션의 최종 세트별 기록 위치가 앱이면 `app_session`, 메모·스프레드시트면 `notes_sheet_session`, 양쪽 또는 다른 위치면 `mixed_other_session`으로 한 번만 센다. 세 번 중 같은 방식이 두 번 이상이면 그 방식을 참가자의 `primary_tool_category`로 쓰고, 세 방식이 각각 한 번이면 `mixed_other`다.
- 세 도구 범주는 각각 유효 참가자 5명 이상이어야 하고, 한 범주는 20명을 초과할 수 없다. 20명에 도달하면 해당 범주 모집을 닫는다.
- 중복 확인을 위해 새 가족·주소 정보는 수집하지 않는다. 일정 연락에 이미 필요한 이메일 또는 전화번호 하나를 데이터 보관자가 연구별 비밀키로 HMAC 처리해 비교하고 원문은 B-02의 연락처 저장소에만 둔다. 약정 시 결제 제공자의 불투명 고객 참조를 비교하고, 내보내기 파일은 승인 저장소에서 SHA-256만 비교한다. HMAC 키·결제 참조·파일 해시는 Git에 저장하지 않는다.
- 모집 담당자, 인터뷰어와 참가자의 사전 관계를 기록하고 결과 요약에 분포를 공개한다.

15명·5명·20명 제한은 모집 쏠림을 줄이기 위한 내부 운영 규칙이며 대표성에 대한 통계적 보장을 뜻하지 않는다. 모집 15영업일 시점에 이 구성을 충족하지 못하면 16절의 20~29명 조건을 만족할 때만 한 번 연장하고, 그 외에는 `STOP`한다.

중복 판정은 HMAC·결제 참조·파일 해시 중 하나가 같다고 자동 확정하지 않는다. 데이터 보관자가 승인 저장소 안에서 일정·동의 시각과 참가자에게 최소 확인 질문을 대조하고, 동일인으로 확인된 경우에만 동의 완료가 빠른 레코드를 남긴다. 확인할 수 없으면 두 레코드를 `disputed`로 두고 표본 동결을 금지한다.

### 금지 질문과 행동

- 콘셉트 노출 전에 “다음 중량을 정하기 어렵지 않나요?”라고 묻지 않는다.
- “AI 추천”, “자동 진행”, “회복 기반 코칭”이라는 해결책을 먼저 말하지 않는다.
- 참가자의 추정 시간을 실제 측정값으로 기록하지 않는다.
- 인터뷰어가 기록을 대신 해석해 문제 신호를 만들어내지 않는다.
- 건강 상태, 질환, 통증을 평가하거나 훈련 처방을 제공하지 않는다.
- 원본 내보내기 파일을 이메일·메신저·Git으로 받지 않는다.

## 10. 콘셉트 카드와 약정 오퍼 통제

콘셉트 카드는 다음 내용만 포함한다.

> 지난 운동 기록과 사용자가 입력한 RPE를 바탕으로 다음 운동의 중량·반복·세트 수 제안을 보여주고, 이유를 확인하거나 직접 수정할 수 있는 Android 근력운동 기록 도구. 기존 기록 가져오기와 오프라인 기록 복구를 우선하며, 의료적 진단·치료를 제공하지 않는다.

회복 데이터 반영은 V1에서 별도 가치 가설로 측정하되 기본 약속에 넣지 않는다. Health Connect의 필요성과 분류가 확인되기 전이기 때문이다.

첫 본 조사 전에 다음 오퍼 필드를 `MEASURE-V1`에 고정한다.

~~~yaml
offer_version: REQUIRED
scope: REQUIRED
delivery_method: REQUIRED
pilot_duration_days: REQUIRED
price_krw: REQUIRED
deposit_krw: REQUIRED
payment_method: REQUIRED
refund_window_days: REQUIRED
refund_trigger: REQUIRED
commitment_observation_window_days: REQUIRED_AND_NOT_SHORTER_THAN_REFUND_WINDOW
participation_incentive_krw: REQUIRED
participation_incentive_payment_condition: INTERVIEW_COMPLETED_REGARDLESS_OF_PRODUCT_OPINION
service_start_condition: REQUIRED
contract_consumer_tax_review_id: REQUIRED
~~~

모든 본 조사 참가자에게 같은 버전을 제시한다. 오퍼를 변경하면 기존 표본과 섞지 않고 새 버전으로 별도 실험한다. 각 참가자의 약정 관찰 종료 시각은 오퍼 제시 시각에 `commitment_observation_window_days`를 더해 계산한다. 마지막 참가자의 관찰창이 닫히기 전에는 V1 표본과 약정 수치를 동결할 수 없다.

`contract_consumer_tax_review_id`에는 계약 주체, 제공하지 못할 때의 전액 환불, 청약·취소·환불 고지, 결제 영수증·세무 처리, 참가 사례비와 예약금의 분리, 데이터 철회 시 환불을 실제 담당자가 승인한 기록이 연결돼야 한다. 실제 돈을 받으므로 `N/A`는 허용하지 않는다. 이 기록이 없으면 결제 링크를 만들거나 제시하지 않는다.

관찰창 종료 전에 전액 또는 일부 환불된 약정은 계수하지 않는다. V1 결정 후에도 B-04가 허용한 환불이 발생해 순약정이 5명 아래로 내려가면 결정 상태를 즉시 `REOPENED`로 바꾸고 V2를 중지한다. 환불 기간이 끝난 뒤 임의로 더 긴 기간을 소급 적용하지 않으며, 더 긴 관찰이 필요하면 새 측정 계획으로 실행한다.

V1 약정 수단은 환불 가능한 예약금 하나로 고정한다. 유료 파일럿 계약과 비환불 결제는 V2 이후 별도 계획으로 미룬다. 참가 사례비는 제품 평가·약정·데이터 보존 동의와 무관하게 인터뷰를 완료하면 지급하며 예약금과 상계하지 않는다. 참가자가 연구 데이터 철회를 요청하면 예약금은 B-04 기한 안에 전액 환불하고 약정 계수에서 제거한다. 데이터 철회 권리나 사례비를 예약금 유지 조건으로 만들 수 없다.

범주별 값이 5명 미만이면 공개 Git에는 정확한 수를 쓰지 않고 `<5`로 표시한다. 핵심 게이트 합계는 판정에 필요하므로 공개 여부를 개인정보 검토자가 따로 승인하며, 승인하지 않으면 Git 결정문에는 `GO/LOOP/STOP`과 증거 배치 ID만 남긴다.

### 내보내기 표본 검증

`export_sample_secured=true`는 다음을 모두 충족할 때만 계산한다.

1. 참가자가 실제 사용 도구의 내보내기 기능으로 생성했고 동의 범위에 파일 관찰·익명화가 포함된다.
2. 원본은 B-02 승인 저장소에 있고 SHA-256, 파일 형식, 생성 시각, 원래 도구 코드가 변환 기록에 남는다.
3. 익명화본은 원본의 파일 컨테이너, 시트·테이블 수, 헤더·필드명, 열 순서, 데이터 타입, 행 경계, 날짜·단위 표기를 유지한다.
4. 이름·이메일·전화번호·계정 ID·자유 메모·위치·기기 ID는 제거 또는 비가역 대체하고, 제거한 필드는 변환 기록에 표시한다. 구조 검증에 필요하지 않은 실제 중량·심박·수면 값은 합성값으로 대체한다.
5. R-PRIVACY가 원본과 익명화본을 대조해 식별정보 제거를 승인하고, R-VERIFY가 원본을 보지 않은 상태에서 익명화본의 파싱·스키마 보고서를 재현한다.
6. 원본 또는 익명화본은 Git에 넣지 않고 Git에는 형식 코드, 변환 기록 ID, 검증 결과와 집계만 남긴다.

암호화·압축·독점 바이너리라 구조를 확인할 수 없거나 익명화 과정에서 헤더·타입·행 경계가 바뀌면 표본으로 세지 않는다.

## 12. 계수와 분석 규칙

1. 판정 단위는 참가자다. 한 사람이 문제를 여러 번 말해도 한 명으로 센다.
2. 분모 30은 유효 참가자만 포함한다. 중복·철회·프로토콜 위반·필수 자료 결손은 참가자 전체를 제외하고 표본 동결 전 동일 모집 규칙으로 다음 적격자를 대체한다.
3. 콘셉트 조기 노출이나 유도 질문이 한 번이라도 확인되면 해당 참가자의 다른 지표도 살리지 않고 전체를 무효화한다.
4. `problem_signal=true`는 관찰 근거 ID와 손실 유형이 둘 다 있어야 한다.
5. `recovery_use_gap=true`는 회복 데이터가 실제로 존재하는 참가자만 판정한다. 데이터가 없으면 `not_applicable`이다.
6. 약정은 B-04에서 승인된 오퍼와 거래 증거가 있고 참가자별 환불 관찰창이 종료됐으며 그 시점에 환불되지 않아야 한다. 조건 없는 관심, 앱 설치 의향, 연락 동의, 비금전 행동은 세지 않는다.
7. 내보내기 표본은 서로 다른 참가자에게서 얻은 실제 파일 또는 구조 보존 익명 형식만 센다.
8. 주 인터뷰어와 독립 검토자가 불일치하면 `disputed`로 두고 합의 근거가 기록되기 전에는 양성으로 세지 않는다.
9. 모든 30건을 독립 검토한다. 일부 표본만 검토해 전체 일치를 추정하지 않는다.
10. 모집 종료 후 임계값, 제외 규칙, 손실 유형을 바꾸지 않는다.

### 표본 동결과 재개방

1. 참가자 ID는 동의 완료 순서로 부여하고, 제외된 ID를 다른 사람에게 재사용하지 않는다.
2. 모집 중 무효·중복·철회가 확인되면 그 참가자를 분모에서 제외하고 같은 프로토콜·채널 상한·도구 범주 규칙으로 다음 적격자를 모집한다.
3. 다음 조건을 모두 충족한 시각을 `sample_frozen_at`으로 기록한다: 유효 30명, 채널·도구 구성 충족, 30건 독립 검토 완료, 모든 약정 환불 관찰창 종료, 미해결 `disputed` 0건.
4. `sample_frozen_at` 이후에 신규 참가자를 추가하거나 양성에 유리한 참가자를 선택적으로 교체하지 않는다.
5. `sample_frozen_at` 이후 V1 결정 전 철회·중복·환불이 확인되면 표본을 수정하거나 대체하지 않고 현재 V1을 `STOP`한다. 새 표본은 새 측정 계획에서만 모집한다.
6. V1 결정 후 V2 시작 전에 철회·뒤늦은 중복·허용된 환불로 임계값이 미달하면 결정을 `REOPENED`로 바꾸고 현재 V1을 `STOP`한다. 기존 표본에 대체 참가자를 삽입하지 않는다.
7. V2 시작 후 근거 무효화로 임계값이 미달하면 V2를 즉시 멈추고 새 V1 측정 계획과 새 표본 없이는 재개하지 않는다.

문제 신호 코딩은 다음 순서를 모두 통과해야 한다.

~~~text
콘셉트 노출 전인가? ── 아니오 ─▶ false
        │ 예
참가자가 먼저 손실을 설명했는가? ── 아니오 ─▶ false
        │ 예
최근 세 번 중 두 번 이상 같은 손실 유형의 근거가 있는가? ── 아니오 ─▶ false
        │ 예
원자료 불투명 ID와 손실 유형이 연결됐는가? ── 아니오 ─▶ disputed
        │ 예
       true
~~~

“참가자가 먼저 설명”했다는 것은 표준 질문 1~9에 답하는 동안 인터뷰어가 손실 유형, 자동화, 추천 또는 어려움의 존재를 이름 붙이기 전에 참가자의 원문 답변에 손실이 나타났다는 뜻이다. 코더는 녹취의 질문·답변 순서와 타임스탬프를 근거로 판정하고, 인터뷰 종료 후 해석 메모만으로 양성을 만들 수 없다.

회복 활용 격차는 데이터 보유 여부를 먼저 판정한다. 데이터가 없으면 `not_applicable`이고 양성으로 세지 않는다. 데이터가 있다면 “수면이 짧으면 세트를 한 개 줄인다”처럼 입력 조건과 조정 행동을 참가자가 설명하고 최근 세 번 중 두 번 이상 기록으로 적용을 보일 때만 반복 가능한 사용으로 인정한다. 조건만 말하거나 한 번 우연히 바꾼 사례는 사용으로 인정하지 않으므로 격차는 `true`다.

R-EVIDENCE와 R-VERIFY는 서로의 레이블을 보기 전에 30건을 독립 코딩한다. 불일치는 원자료를 새로 수집하거나 참가자를 재질문하지 않고, R-USER가 이 문서의 결정 트리와 사전 등록 enum만 적용해 제3자 판정한다. 판정 근거와 변경 전 두 레이블을 보존한다. R-USER가 이해충돌이 있거나 규칙만으로 판정할 수 없으면 해당 참가자 전체를 `disputed`로 제외하며 합의를 위해 기준을 바꾸지 않는다. 이 제외가 `sample_frozen_at` 전이고 활성 모집 기간 안이면 채널·도구 상한을 지켜 다음 적격자로 대체한다. `disputed` 제외 건은 20~29명 연장 자격의 유효 인원에도 포함하지 않으며, 모집 시간 상한을 넘기면 V1은 `STOP`이다.

집계표는 최소 다음 분모를 함께 표시한다.

| 지표 | 분자 | 분모 |
|---|---:|---:|
| 문제 신호 | 유효 참가자 중 `problem_signal=true` | 30 |
| 회복 활용 격차 | `recovery_use_gap=true` | 회복 데이터 보유 유효 참가자 수와 전체 30을 둘 다 표시 |
| 실제 약정 | `commitment_completed=true` | 동일 오퍼를 본 유효 참가자 수와 전체 30을 둘 다 표시 |
| 내보내기 표본 | `export_sample_secured=true` | 30 |

## 13. V0 실행 작업

### 브랜드 후보 계수 규칙

후보 정규화는 Unicode NFKC 적용, 영문 소문자화, 공백·하이픈·구두점 제거 순서로 수행한다. 정규화 문자열이 같은 후보는 한 개로 센다. 발음·의미의 다양성은 후보 수 조건이 아니다.

V0에서 “구별 가능한 후보”로 세려면 한국 기준 조사에서 다음을 모두 충족해야 한다.

1. 공백·대소문자·구두점을 정규화한 동일 명칭의 활성 피트니스·건강 앱 또는 서비스가 한국 Google Play·App Store와 일반 웹 검색에서 발견되지 않는다.
2. KIPRIS 9류·42류 검색에서 동일 명칭과 겹치는 지정상품·서비스가 발견되지 않거나, 발견된 경우 상표 전문가가 서면으로 다음 단계 진행 가능 범위를 남긴다.
3. 정확명, 띄어쓰기·하이픈 변형, 한글 표기, 영문 표기, 통용 로마자 표기와 발음 유사어를 각각 검색한다.
4. B-05에 사전 등록한 도메인 패턴 중 실제 등록 가능한 하나와 필수 공식 계정 플랫폼 모두에서 사용 가능한 식별자가 있다. `.com` 단일 도메인 보유를 임의로 필수화하지 않는다.
5. 조사 결과를 “상표 사용 가능”이 아니라 “해당 질의에서 명백한 충돌 미발견” 또는 전문가의 제한된 결론으로 표현한다.
6. 상표 전문가가 후보의 검색표·지정상품·서비스를 검토하고 한국 V0 단계의 서면 예비 진행 의견을 남긴다.

위험 등급은 다음처럼 고정한다.

V1 `GO`는 위 조건을 모두 충족해야 한다. `GO`가 허용하는 다음 작업은 V2 컨시어지 가치 실험의 상세 계획 작성뿐이다. [V2 랜딩 수요 실험 계획](./fitpulse-v2-landing-demand-experiment-plan-20260814.md)은 이 상세 계획에 들어갈 `V2-A` 초안이며, V1 `GO`와 실제 `MEASURE-V2-LP` 승인 전에는 실행할 수 없다. 랜딩의 클릭·설문·대기자 수는 V1의 실제 약정이나 V2 컨시어지 결과를 대신하지 않는다. 제품 코드, Health Connect, LLM, 공개 베타는 계속 금지된다.

### V1 `LOOP`와 `STOP`의 결정 규칙

1. 파일럿에서 절차 문제가 발견되면 프로토콜을 한 번 개정하고 새 파일럿 3명을 한 번만 실행한다. 두 번째 파일럿에도 유도·필수 관찰 누락·저장·삭제 실패가 하나라도 있으면 `STOP`이다.
2. 본 조사 첫 모집 기간은 15영업일이다. 종료 시 유효 20~29명이고 연구 전체 차단 사건이 없을 때만 동일 프로토콜로 10영업일 연장한다.
3. 첫 모집 기간 종료 시 유효 20명 미만이면 모집 경로가 검증되지 않은 것으로 `STOP`한다. 임계값을 낮추거나 기간을 반복 연장하지 않는다.
4. 연장 종료 시 유효 30명 또는 채널·도구 구성 조건을 충족하지 못하면 `STOP`한다.
5. `sample_frozen_at` 이후 문제 10명, 회복 격차 10명, 순약정 5명, 내보내기 5명 중 하나라도 미달하면 현재 웨지는 `STOP`이다. 같은 오퍼에 참가자를 추가하는 `LOOP`는 허용하지 않는다.
6. 다른 대상·문제·오퍼를 시험하는 일은 새 `MEASURE-V1`과 새 표본으로 시작하며, 기존 `STOP` 결정을 `LOOP`로 바꾸지 않는다.

연구 전체 차단 사건은 다음 중 하나다: 무동의 수집, 승인 저장소 밖 원자료 전송, 무단 접근, 철회·삭제 실행 실패, 본 조사 시작 후 핵심 질문·오퍼·계수 규칙 변경, 같은 인터뷰어의 유도 또는 콘셉트 조기 노출이 두 명 이상에서 반복, 서로 다른 오퍼 버전의 표본 혼합, 결과 확인 후 임계값 변경. 단일 참가자의 비체계적 프로토콜 위반은 그 참가자 전체를 제외하고 표본 동결 전에 대체하되 연구 전체 차단 사건으로 확대하지 않는다.

여기서 핵심 질문 변경은 9절 질문 1~9의 의미·순서, 콘셉트 카드, 자격 기준, 오퍼 필드 또는 계수 결정 트리를 바꾸는 것이다. “반복”은 같은 인터뷰어·프로토콜 버전에서 두 명 이상에게 동일 위반이 확인된 경우다. “승인 저장소 밖 전송”은 B-02에 등록되지 않은 기기·클라우드·이메일·메신저로 원자료 바이트를 복사하거나 열람 가능하게 만든 경우다. “무단 접근”은 B-02 접근 행렬에 없는 역할·계정이 원자료를 열람하거나 내보낼 수 있었던 경우다. “삭제 실패”는 B-02의 삭제 기한까지 운영본·매핑·적용 파생자료·백업 중 하나라도 처리 결과를 검증하지 못한 경우다.

### 사건 판정과 접근 절차

1. 누구든 사건 후보를 발견하면 수집을 즉시 멈추고 R-EVIDENCE가 불투명 사건 ID, 발견 시각, 프로토콜 버전, 영향 자료·참가자 범위만 사건 대장에 기록한다.
2. 개인정보·동의·접근·삭제 사건은 R-PRIVACY가 조사 책임자이자 거부권자다. 질문·오퍼·표본·계수 사건은 R-VERIFY가 조사하고 R-USER가 공동 판정한다.
3. 조사 책임자는 1영업일 안에 격리, 삭제·접근 차단, 참가자 통지 필요성, 단일 참가자 무효인지 연구 전체 차단인지, 추가 전문 검토 필요성을 기록한다. 확인 불가능하면 더 높은 등급으로 처리한다.
4. 연구 전체 차단 사건이면 현재 V1은 `STOP`이며 같은 계획에서 복구·재개하지 않는다. 사건 종료, 삭제·통지, 원인·재발 방지 검토 후 새 측정 계획을 승인해야 한다.
5. 단일 참가자 위반이면 그 참가자를 전체 제외하고 활성 모집 기간 안에서만 대체한다. 두 번째 동일 위반이 확인되는 즉시 연구 전체 차단으로 승격한다.
6. B-02는 R-VERIFY에게 승인 저장소의 참가자 분류 레코드·녹취 구간·거래 증거의 최소 읽기 권한을 사전에 부여해야 한다. 연락처·결제 원문 대신 가림 처리된 증거를 제공하며, 재현에 부족하면 V1은 `STOP`이다.
7. R-PRIVACY가 공개 Git에 핵심 합계를 쓰지 못하게 하면 R-VERIFY는 제한 저장소에서 동일 집계를 재현하고 서명된 검증 보고서 ID와 `GO/LOOP/STOP`만 Git에 남긴다. 공개 불가가 독립 검토 불가를 뜻하지 않는다.

## 18. 롤백과 중단

- 문서 오류는 새 버전으로 수정하고 기존 승인본을 `SUPERSEDED`로 표시한다. 승인 이력을 삭제하지 않는다.
- 본 조사 전 프로토콜 변경은 파일럿을 폐기하고 새 버전으로 다시 동결한다.
- 본 조사 시작 후 핵심 질문·오퍼·계수 규칙을 바꾸면 이전 표본과 섞지 않고 새 실험으로 분리한다.
- 개인정보·동의 위반은 즉시 수집을 멈추고 영향 원자료를 격리한다. 개인정보 검토자가 삭제·통지·사건 대응 범위를 결정할 때까지 재개하지 않는다.
- 철회 시 승인 저장소의 녹취·화면 공유·내보내기 파일·관찰 레코드·신원 매핑 키를 삭제한다. 법령·계약상 결제 감사 기록을 보존해야 한다면 B-04의 법적 근거·항목·기간만 접근 봉쇄 상태로 남기고 분석에서 제외한다.
- 철회 참가자가 포함된 외부 파생표는 해당 행을 제거해 재생성한다. 공개 Git에는 참가자별 행이 없으므로 기존 집계 EVD를 삭제하지 않고 `EVIDENCE_INVALIDATED`로 표시한 새 버전과 재계산 집계를 추가한다. 이전 Git 집계가 5명 미만 셀을 노출했다면 개인정보 사건으로 상향한다.
- 즉시 선택 삭제할 수 없는 백업은 접근을 봉쇄하고 B-02에 등록된 다음 순환 삭제일과 실행·검증자를 기록한다. 백업 복구 시 철회 목록을 먼저 재적용한다.
- 브랜드 후보가 탈락하면 후보 상태만 `REJECTED`로 남긴다. 해당 이름으로 UI·도메인·스토어 자산을 만들지 않았으므로 제품 롤백은 없다.
- V1 `STOP`은 실패한 제품 코드를 되돌리는 일이 아니라 구현하지 않기로 결정하는 것이다.

## 19. 수용 기준

### 이 계획의 승인 기준

1. B-00~B-05의 실제 값이 승인 기록에 존재하고, V0 측정 계획에는 역할 ID·승인 기록 ID·확인일이 기록된다.
2. V0·V1 산출물 경로, 원자료 비저장 규칙, 역할 분리 규칙이 독립 검토자에게 동일하게 해석된다.
3. 모집 기준 8개, 파일럿 3명, 본 조사 30명, `10/10/5/5` 판정이 측정 계획과 이 문서에서 일치한다.
4. 문제 신호, 회복 활용 격차, 실제 약정, 내보내기 표본의 계수 정의에 주관적 빈칸이 없다.
5. 약정 오퍼의 필수 필드가 전부 실제 값으로 채워지기 전 약정 수집이 차단된다.
6. 참가자 원자료·연락처·건강정보·결제 원문이 Git에 저장되지 않는다.
7. `GO`가 제품 구현 승인이 아니라 V2 상세 계획 승인임을 V1 결정문이 명시한다.

### V1 종료 기준

1. 유효 30건, 제외·철회·중복·프로토콜 위반 건수와 사유가 모두 집계된다.
2. 30건 전부에 주 검토와 독립 검토 상태가 있고 미해결 `disputed`를 양성으로 세지 않는다.
3. 각 양성 계수는 불투명한 원자료 ID와 연결되며 Git에는 식별 가능한 원문이 없다.
4. 동일 입력 집계표를 R-EVIDENCE와 R-VERIFY가 각각 실행해 유효 표본·문제·회복·약정·내보내기 다섯 판정 수치가 일치한다.
5. 결정문이 임계값을 변경하지 않고 `GO/LOOP/STOP`, 허용 다음 작업, 금지 작업과 재검증 조건을 기록한다.
