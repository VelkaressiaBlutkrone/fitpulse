Applies to: V2-A message and acquisition experiment only

Product implementation authorized: **NO**

> 현재 `PREVALIDATION_LITE` 단계에는 이 문서의 V1 선행 게이트와 유료 약정 절차를 적용하지 않는다. 현재 기준은 [ADR-20260814-002](../decisions/ADR-20260814-002-prevalidation-lite-landing-first.md)와 [랜딩·데이터 검증 실행 계획](./fitpulse-landing-data-validation-execution-plan-20260814.md)이다. 이 문서는 결제·약정 또는 정식 서비스 검증을 시작할 때 참고한다.

## 결론

이 계획은 V1에서 확인된 **하나의 고객·하나의 문제·하나의 오퍼**를 대상으로 메시지 반응과 실제 약정 전환을 측정한다. 부상 회피와 회복 조절처럼 서로 다른 제품을 같은 A/B 테스트에서 경쟁시키지 않는다.

랜딩 실험은 V2 컨시어지 가치 검증의 보조 단계 `V2-A`다. 랜딩 전환만으로 제품 가치, 유지율 또는 구현 착수를 승인하지 않는다.

증거 위계는 다음과 같다.

1. 고정된 오퍼에 대한 실제 환불 가능 예약금 또는 승인된 유료 약정
2. 자격이 확인된 사용자의 오퍼 신청 완료
3. 자격이 확인된 사용자의 알림 등록
4. 가격 버튼 클릭
5. 설문 지불 의향

하위 행동은 상위 행동으로 바꿔 세지 않는다. 특히 가짜문 클릭은 결제가 아니다.

## 1. 이 계획의 위치

~~~text
V0 브랜드·권한 GO
        ▼
V1 문제 관찰 30명 + 10/10/5/5 + 소유자 자체 검산
        │
        ├─ STOP ─▶ 이 문서 실행 금지
        │
        ▼ GO
V2 상세 계획 승인
        ▼
V2-A 랜딩 메시지·오퍼 실험  ──▶ 메시지·획득 경로 근거
        ▼
V2-B 수작업 컨시어지 가치 실험 ──▶ 결과·반복 사용·결제 유지 근거
        ▼
V3 사용성·기술·규제 준비
~~~

이 문서를 미리 작성한 것은 실행 계약의 빈칸과 금지 범위를 드러내기 위한 것이다. V1 결과를 미리 채우거나 V2 진입을 승인하는 문서가 아니다. V1이 `GO`여도 R-SPONSOR와 필수 검토자가 실제 값을 채운 `MEASURE-V2-LP`를 별도로 승인해야 한다.

## 3. 가설과 반증 조건

### H-LP1 — 메시지 이해

자격을 충족한 사용자는 페이지를 본 뒤 제품이 해결하려는 한 작업을 해결책 단어 없이 자신의 말로 설명할 수 있다.

반증: 이해 확인 응답이 다른 문제·의료 기능·범용 건강 앱으로 일관되게 해석되거나, 시안이 실제 구현으로 오인된다.

### H-LP2 — 획득 가능성

사전 등록한 채널과 비용 안에서 자격을 충족한 사용자가 오퍼 단계까지 도달한다.

반증: 유입은 생기지만 자격 확인 뒤 남는 사람이 없거나, 목표 표본을 얻는 비용이 사전 예산 상한을 넘는다.

### H-LP3 — 오퍼 행동

동일 범위·가격·기간·환불 조건을 본 적격 사용자가 실제 환불 가능 예약금 또는 승인된 약정 행동을 완료한다.

반증: 클릭·무료 등록은 발생하지만 사전 등록한 실제 약정 임계값이 충족되지 않는다.

### H-LP4 — 메시지 선택

같은 웨지와 오퍼를 설명하는 두 Hero 카피 중 하나가 사전 등록한 판단 규칙에서 우세하다.

반증: 표본 상한에서 차이를 판정하지 못하거나 지표별 승자가 달라 단일 우세안을 고를 수 없다.

이 가설들의 통과 수치는 외부 업계 표준이 아니다. `MEASURE-V2-LP` 승인 전에 실제 예산, 기준 전환율과 의사결정에 필요한 최소 차이로 계산한다.

## 4. 실험 단위와 A/B 규칙

### 4.1 비교할 수 있는 것

두 안은 다음 항목이 같아야 한다.

- 대상 사용자와 자격 기준
- 선택된 문제와 제품 웨지
- 페이지 섹션 순서·목업·신뢰 문구
- 가격·예약금·환불·제공 범위
- CTA 위치·색·크기·입력 필드
- 채널별 트래픽 배분
- 로딩 성능과 기기 지원

다르게 할 수 있는 것은 다음 세 필드뿐이다.

1. Hero H1
2. Hero 보조 문구
3. 해결 흐름 세 단계 중 한 문장의 표현

부상 회피 제품과 회복 조절 제품을 A/B안으로 두지 않는다. 서로 다른 문제나 오퍼를 시험하려면 별도 `MEASURE-V2-LP`와 별도 표본을 사용한다.

### 4.2 배정

- 프로덕션 유입은 한 URL에서 50:50 무작위 배정한다.
- 한 브라우저는 실험 기간 동안 같은 변형을 본다.
- 이메일·전화번호·건강정보를 배정 키로 사용하지 않는다.
- 배정 식별자는 가명 온라인 식별자로 데이터 맵에 등록하고 목적·보존기간·처리 근거를 승인한다. 비필수 저장 동의가 필요한 구성이라면 동의 전 식별자를 만들지 않는다.
- QA 전용 `?variant=`는 승인된 테스트 환경에서만 허용하고 실험 집계에서 제외한다.
- 채널별로 A/B URL을 나누지 않는다. 채널과 변형 효과가 섞이기 때문이다.
- 14일 관찰 중 우세해 보인다는 이유로 7:3으로 재배분하지 않는다.
- 개인정보·안전·기능 장애가 아니면 중간 결과를 보고 한 안을 조기 중단하지 않는다.

### 4.3 표본 크기와 판정 방법

고정된 `각 안 400세션`을 기본값으로 사용하지 않는다. `R-OWNER`는 `R-VERIFY` 기능으로 다음 두 방식 중 하나를 `MEASURE-V2-LP`에 결과 확인 전에 고정한다.

| 방식 | 사전 등록 필드 |
|---|---|
| 빈도주의 | 기준 전환율 출처, 최소 탐지 차이, 유의수준, 검정력, 양측/단측, 안별 표본 수, 다중 지표 처리 |
| 베이지안 | 사전분포 근거, 우세 확률 임계값, 최소 실질 차이, 최대 표본, 중단 규칙 |

방식을 결과 확인 후 바꿀 수 없다. 기준 전환율이 없으면 비계수 계측 파일럿으로 값을 얻은 뒤 새 측정 계획을 동결한다. 파일럿 방문은 본 실험 표본에 포함하지 않는다.

## 5. 14일 관찰창

14일은 **트래픽 수집 상한**이다. 준비·개인정보 검토·계측 QA는 Day 1 전에 끝낸다.

| 시점 | 작업 | 금지 |
|---|---|---|
| Pre-Day 1 | 공급자·카피·오퍼·측정 계획 승인, 테스트 트래픽 제거 | 실제 신청·광고비 집행 |
| Day 1 | `launch_gate_at` 기록, 50:50 배정 시작 | 카피·오퍼 수정 |
| Day 1~3 | 이벤트 결손·중복·봇·결제 장애만 점검 | 승자 판정·트래픽 재배분 |
| Day 4~10 | 승인 채널 동일 운영 | 새 채널·새 혜택 추가 |
| Day 11~14 | 표본·예산 상한까지 유지, 종료 준비 | 임계값 변경·마감 압박 카피 추가 |
| Day 14 | 신규 유입 종료, `traffic_collection_ends_at` 기록 | 미달 보충을 위한 임의 연장 |
| 이후 | 환불 관찰창 종료, 소유자 자체 재집계, 결정 | 관찰창이 열린 약정을 순약정으로 계수 |

Day 14에 필요한 표본을 얻지 못하면 결과는 `INCONCLUSIVE`다. 같은 표본에 기간을 붙이지 않는다. 다시 실행하려면 미달 원인과 새 예산·채널을 가진 새 측정 계획을 승인한다.

예약금 환불 관찰창이 Day 14 뒤에 끝나면 최종 오퍼 판정도 그 뒤에 한다. 14일 안에 결과를 발표하기 위해 환불창을 줄이지 않는다.

## 6. 퍼널과 분모

### 6.1 퍼널

~~~text
광고·커뮤니티·제휴 유입
        ▼
고유 랜딩 노출 ─▶ Hero 변형 고정
        ▼
CTA 클릭
        ▼
최소 자격 확인
        ├─ 부적격 ─▶ 종료, 수요 분모에서 분리
        ▼
적격 오퍼 노출
        ├─ 이탈
        ├─ 알림 등록
        ├─ 가짜문/오퍼 신청
        └─ 실제 예약금 또는 승인 약정
                 ▼
          환불 관찰창 종료
~~~

### 6.2 운영 정의

| 용어 | 정의 |
|---|---|
| 고유 랜딩 노출 | 봇·QA·중복 새로고침을 제외하고 한 배정 키가 페이지의 Hero를 정상 렌더링한 첫 세션 |
| 적격 오퍼 노출 | 사전 자격 기준을 통과한 고유 사용자가 같은 오퍼 버전의 범위·가격·환불 조건을 모두 본 상태 |
| 등록 완료 | 연락 목적·보유기간에 동의하고 검증 가능한 연락 수단 하나를 제출한 상태 |
| 가짜문 클릭 | 가격·오퍼 CTA를 눌렀지만 거래가 없는 상태. 지불 증거 아님 |
| 오퍼 신청 완료 | 제공 범위와 연락 조건에 동의했지만 금전 약정이 없는 상태 |
| 실제 약정 | 승인된 결제·환불 조건과 관찰창을 충족한 예약금 또는 유료 계약. V1 정의보다 약한 행동으로 대체 금지 |
| 순약정 | 관찰창이 닫힌 시점에 환불·취소·분쟁·철회로 제거되지 않은 실제 약정 |
| 자격 확인 설문 | 퍼널 분모 분리를 위한 최소 질문. 문제·WTP 설문과 구분 |
| 진단 설문 | 페이지 이해·거부 이유를 묻는 선택 설문. 게이트 분자 아님 |

### 6.3 필수 분모

| 지표 | 분자 | 분모 |
|---|---:|---:|
| 방문→CTA | CTA를 한 번 이상 클릭한 고유 배정 키 | 고유 랜딩 노출 |
| 적격 등록 | 적격 등록 완료 | 적격 자격 확인 완료 |
| 가격 관심 | 가짜문 클릭 | 적격 오퍼 노출 |
| 오퍼 신청 | 오퍼 신청 완료 | 적격 오퍼 노출 |
| 실제 약정 | 순약정 | 적격 오퍼 노출 |
| 채널 CPL | 해당 채널의 승인된 변동 모집비 | 해당 채널 적격 등록 완료 수 |
| 채널 CPA | 해당 채널의 승인된 변동 모집비 | 해당 채널 순약정 수 |

분모가 다른 전환율을 합치지 않는다. 퍼널 A의 랜딩 유입과 커뮤니티 설문 직링크를 한 대기자 수로 합산하지 않는다.

CPL·CPA 분모가 0이면 값을 `0`이나 임의의 큰 수로 기록하지 않고 `undefined_zero_conversion`으로 표시한다. 비용은 그대로 공개하고 0 전환 사실을 함께 남긴다.

## 7. 판정 상태

| 판정 | 조건 | 허용 다음 작업 |
|---|---|---|
| `MESSAGE_GO` | 사전 표본 충족, 한 변형이 사전 판단 규칙 통과, 이해 오인 기준 미발생 | 선택 카피를 V2-B 모집에 사용 |
| `OFFER_GO` | `MESSAGE_GO`, 사전 등록 순약정·CPA·예산 조건 모두 통과 | 같은 오퍼로 V2-B 컨시어지 계획 실행 검토 |
| `MESSAGE_ONLY` | 메시지는 판정됐으나 실제 약정 조건 미달·미측정 | 카피 선택만 허용, V2 가치·구현 진입 금지 |
| `INCONCLUSIVE` | 14일 내 표본 미달, 계측 결손, A/B 우세 불명확 | 원인 문서화 후 새 측정 계획만 허용 |
| `STOP` | 동결 표본에서 오퍼 기준 미달 또는 연구 전체 차단 사건 | 현재 메시지·오퍼 폐기, 구현 금지 |

원안의 `대기자 300 AND WTP 30% AND 우세안 명확`은 자동 GO 규칙으로 채택하지 않는다. 대기자 수는 구매 의사가 아니라 유입 예산·채널·혜택의 영향을 함께 받는다. 설문 WTP와 클릭도 순약정을 대신하지 않는다.

다음 경우 판정 우선순위를 적용한다.

1. 개인정보·안전 사건이 있으면 다른 수치와 관계없이 `STOP`한다.
2. 표본·계측이 불충분하면 `INCONCLUSIVE`다.
3. 표본이 충분한 뒤 실제 약정 기준이 미달이면 `STOP`이다.
4. 메시지만 통과하면 `MESSAGE_ONLY`이며 `OFFER_GO`로 올리지 않는다.

## 8. 페이지 구조와 카피 계약

페이지는 모바일 우선 단일 페이지 7개 섹션을 사용한다. 아래는 카피 형식이며 실제 문장은 V1 근거와 오퍼를 입력해 `MEASURE-V2-LP`에서 동결한다.

| # | 섹션 | 필수 내용 | 금지 |
|---:|---|---|---|
| 1 | Hero | 선택된 한 문제, 한 결과, 한 CTA | 두 웨지 결합·기술 스택 |
| 2 | 현재 작업 | V1에서 확인된 업무 단계와 손실의 비식별 집계 | 근거 없는 시장 수치·소수 셀 인용 |
| 3 | 제공 방식 | 입력→결과→사용자 결정의 세 단계 | 구현되지 않은 자동화 과장 |
| 4 | 콘셉트 미리보기 | 목업과 “개발 전 검증용 시안” 배지 | 실제 앱 화면처럼 표현 |
| 5 | 범위·신뢰 | 사용자 통제, 데이터 최소화, 의료 비목적 | 면책만으로 안전 보장 |
| 6 | 오퍼 | 실제 범위·기간·가격·예약금·환불 조건 | 미승인 무료·평생·출시 약속 |
| 7 | FAQ·최종 CTA | 제공 전 조건, 환불, 데이터, 미구현 상태 | Apple Watch·iOS·Health Connect 미승인 주장 |

### 8.1 Hero 템플릿

~~~text
[H1]
{V1에서 확인된 사용자의 한 작업 또는 반복 손실}

[보조 문구]
{현재 입력}을 바탕으로 {검증할 한 결과}를 제공합니다.
{사용자가 수정·거부할 수 있는 범위}를 함께 알립니다.

[CTA]
{고정 오퍼 행동}

[투명성 문구]
현재 개발 전 검증 단계입니다. 화면은 실제 구현이 아닌 시안입니다.
~~~

H1에 “AI”, “스마트”, “혁신” 같은 구현 수단을 넣지 않는다. 실제 사용자가 수행하는 작업과 결과를 쓴다.

### 8.2 콘셉트 목업

목업은 V1에서 선택된 웨지에 필요한 화면만 사용한다. 세 장을 만들어야 한다는 고정 규칙은 없다. 각 목업에는 다음을 표시한다.

- `개발 전 검증용 시안`
- 실제 제공되지 않는 기능 목록
- 합성 데이터 사용 표시
- 오퍼가 보장하는 결과와 보장하지 않는 결과

운동·심박·수면·통증 값은 실제 참가자 데이터를 사용하지 않는다.

### 8.3 오퍼 카드

~~~text
[제공 범위]
{offer_scope}

[제공 방식과 기간]
{offer_delivery_method} / {pilot_duration_days 또는 실제 기간}

[가격과 예약금]
{price_krw} / {deposit_krw}

[환불]
{refund_trigger} / {refund_window_days}

[서비스 시작 조건]
{service_start_condition}

[CTA]
{승인된 실제 약정 행동}
~~~

값이 하나라도 없으면 가짜 값이나 `예정`으로 공개하지 않고 오퍼 섹션 자체를 게시하지 않는다. 오퍼 섹션이 없으면 `OFFER_GO`를 판정할 수 없다.

## 10. 선택 진단 설문

진단 설문은 오퍼 행동 뒤 또는 이탈 의사를 명시한 사용자에게 선택적으로 제시한다. 문제·지불 게이트로 계수하지 않는다.

1. “이 페이지가 무엇을 제공한다고 이해하셨나요?” — 자유서술
2. “지금 이 결과를 얻기 위해 어떤 방법을 쓰고 계신가요?” — 자유서술
3. “진행하지 않은 가장 큰 이유는 무엇인가요?” — 자유서술 후 분류
4. “설명이 실제 앱처럼 느껴졌나요, 개발 전 시안처럼 느껴졌나요?” — 단일 선택
5. “후속 인터뷰 연락을 받아도 될까요?” — 별도 동의와 연락처 분리

가격을 묻는다면 두 가치 제안을 한 문장에 합치지 않는다. `바로 쓸 것`, `무료 체험 후 결정` 같은 응답은 태도 데이터로만 저장한다.

설문 완료 목표를 랜딩 GO 조건으로 두지 않는다. 응답 수가 적으면 진단 설문만 `INCONCLUSIVE`로 기록하고 랜딩 퍼널 분모와 합산하지 않는다.

## 11. 개인정보·안전·플랫폼 경계

### 11.1 개인정보

- 공개 페이지 분석, 자격 확인, 연락처, 연구 응답, 결제 증거를 목적별로 분리한다.
- 이메일·전화번호·운동·건강정보를 URL, UTM, 분석 파라미터나 세션 녹화로 보내지 않는다.
- 건강·부상 질문이 필요하면 별도 민감정보 처리 근거·동의와 안전조치를 승인한다.
- 실제 국외 이전 경로가 있으면 항목·국가·시기·방법·수령자와 연락처·목적·기간·거부 방법과 효과를 실제 값으로 고지한다.
- 철회 시 연구 데이터와 약정 계수 처리, 계약상 필요한 결제 감사 기록의 범위를 B-04에 고정한다.
- 공개 Git에는 참가자별 행, 직접 인용, 연락처, 결제 원문을 저장하지 않는다.

### 11.2 세션 녹화와 분석

- 스크리너·동의·결제·완료 페이지에서 세션 녹화 도구를 로드하지 않는다.
- 비민감 공개 섹션에서도 `R-OWNER`의 개인정보 자체 검토와 엄격한 마스킹 검증 전에는 사용하지 않는다.
- 마스킹 설정 변경이 기존 녹화에 소급되는지 공급자 문서로 확인한다.
- 비필수 분석을 거부해도 페이지·오퍼 흐름이 동작해야 한다.

### 11.3 제품·의료 주장

다음 표현은 별도 분류·안전 근거 없이는 금지한다.

- 안전한 루틴, 금기 운동을 자동으로 판정
- 통증·부상 위험 감소 보장
- 정상·비정상, 과훈련, 회복 완료
- 치료·재활·의사·물리치료사를 대체
- 수면·심박만으로 운동 강도를 자동 확정

### 11.4 기기

Android 범위에서 Apple Watch 연결을 약속하지 않는다. Apple의 공식 호환 문서는 Apple Watch 모델별로 호환 iPhone과 iOS를 제시한다. iOS·watchOS 경로가 별도 승인되기 전에는 Apple Watch를 지원 기기 목록에서 제외한다.

## 12. 기술 구성 선택 기준

랜딩은 검증 도구이므로 제품 백엔드를 만들지 않는다. 그렇다고 특정 무료 SaaS를 자동 선택하지도 않는다.

| 구성 | 필수 능력 |
|---|---|
| 페이지 호스트 | 한 URL 무작위 배정 또는 승인된 엣지 배정, 커스텀 스크립트 통제, 종료 스위치 |
| 폼 | 조건 분기, 중복 방지, 승인 저장소 전송, 삭제·내보내기 |
| 결제 | 환불 가능 예약금, 거래 증거, 환불·분쟁 상태, 계약 주체 표시 |
| 메일 | 목적별 동의, 1회성 운영 안내와 마케팅 분리, 수신 거부 |
| 분석 | 커스텀 이벤트, 봇·QA 제외, PII 필터, 데이터 보존 설정 |
| 저장소 | 연락처·응답·결제 참조 분리, 역할별 접근, 삭제·백업 전파 |

Framer/Carrd+Tally 또는 Next.js 같은 구현 선택은 다음 산식으로 비교한다.

~~~text
총 검증 비용 = 제작 시간 + 도구 비용 + 개인정보 검토 비용
             + 계측 오류 복구 비용 + 삭제·내보내기 운영 비용
~~~

코드 자산이 남는다는 이유만으로 제품 스택을 사용하지 않는다. 반대로 빠르다는 이유로 데이터 경계를 확인할 수 없는 도구를 사용하지 않는다.

## 13. 이벤트 계약

실제 분석 공급자가 승인된 경우 다음 이벤트를 사용한다.

| 이벤트 | 발생 조건 | 허용 파라미터 |
|---|---|---|
| `landing_view` | 고유 랜딩 노출 | `experiment_id`, `variant`, `channel_code`, `page_version` |
| `scroll_depth` | 50% 또는 90% 최초 도달 | 위 값 + `depth_bucket` |
| `primary_cta_click` | Hero/최종 CTA 최초 클릭 | 위 값 + `position` |
| `eligibility_start` | 최소 자격 확인 시작 | 위 값 |
| `eligible_offer_view` | 적격 사용자가 전체 오퍼를 봄 | 위 값 + `offer_version` |
| `price_cta_click` | 가격 CTA 최초 클릭 | 위 값 + `offer_version` |
| `offer_application_complete` | 비금전 신청 완료 | 위 값 + `offer_version` |
| `optional_survey_complete` | 선택 설문 완료 | 위 값. 응답 내용 제외 |

금지 파라미터:

- 이메일·전화번호·이름·계정 ID
- 전체 URL·자유서술·폼 값
- 운동명·중량·RPE·수면·심박·체중·통증·부상
- 결제 거래 ID·카드·계좌·영수증 원문

실제 약정·환불 상태는 일반 페이지 분석 이벤트로 보내지 않는다. 승인 연구 저장소에서 가명 실험 배정 ID와 결제 제공자의 불투명 참조를 최소 범위로 대조하며, 승인 결제 원장의 거래·환불 상태와 환불 관찰창을 적용한 외부 집계가 권위다.

## 14. 채널과 비용

채널은 `MEASURE-V2-LP`에 코드, 예산, 담당자, 허가 근거와 대상 적합성을 등록한다.

| 채널 유형 | 허용 전 확인 |
|---|---|
| 공개 커뮤니티 | 홍보·조사 링크 규정과 운영자 허가 |
| 코치·체육시설 제휴 | 모집 문구 승인, 강요·의료 오인 방지, 보상 관계 공개 |
| 유료 광고 | 계정 소유자, 최대 예산, 타기팅 항목, 건강·민감 속성 사용 금지 검토 |
| 지인·추천 | 별도 코드, 사전 관계 기록, 결과 분리 |
| 오프라인 QR | 게시 장소 허가, 종료 후 회수 책임자 |

10만~20만원으로 특정 방문 수를 얻는다고 가정하지 않는다. 계측 파일럿 또는 채널의 실제 비용 자료 없이 CPC·CPL·CPA를 채우지 않는다.

## 16. 데이터 품질과 소유자 자체 검산

`R-OWNER`는 `R-EVIDENCE` 기능의 1차 집계를 동결한 뒤, 첫 결과를 보지 않은 별도 단계에서 `R-VERIFY` 기능으로 다음 집계를 다시 실행한다. 이는 인적 독립 검증이 아니며 결과에 `independent_assurance_claimed: false`를 기록한다.

1. QA·봇·중복 제거 후 고유 노출 수
2. 변형·채널별 적격 오퍼 노출 수
3. CTA·등록·신청·실제 약정 분자와 분모
4. 환불 관찰창 종료 후 순약정
5. 채널별 승인 비용과 CPL·CPA
6. 누락 이벤트·차단 사용자·실패 거래
7. 개인정보·카피·오퍼 버전 사건

두 집계가 일치하지 않으면 더 유리한 값을 선택하지 않는다. 원인을 찾고 `disputed`로 둔 뒤 최종 판정을 금지한다.

공개 Git 집계는 5명 미만 세그먼트 셀을 `<5`로 억제한다. 핵심 합계 공개 여부는 `R-OWNER`가 개인정보 기능 체크리스트로 판단하며, 공개할 수 없으면 결정과 제한 저장소의 자체 검산 보고서 ID만 남긴다.

## 18. 롤백과 종료

- 개인정보·결제·의료 오인 사건이 발생하면 광고와 신규 신청을 먼저 중단한다.
- 페이지를 `CLOSED`로 전환해도 환불, 철회, 문의와 개인정보 권리 행사 경로는 유지한다.
- 오퍼 또는 카피 변경은 기존 표본에 덮어쓰지 않고 새 버전·새 측정 계획으로 실행한다.
- 원자료는 B-02/B-04 수명주기에 따라 삭제·보존하며 Git 결정 기록은 몰래 지우지 않고 `EVIDENCE_INVALIDATED` 또는 `SUPERSEDED`로 표시한다.
- V1 근거가 철회·무효화돼 임계값 아래로 내려가면 V2-A를 즉시 멈추고 새 V1 없이 재개하지 않는다.
- 랜딩 `OFFER_GO`도 V2-B에서 결과·반복 사용이 실패하면 제품 구현 근거로 남지 않는다.

## 21. 승인 기준

이 문서의 실행본은 다음을 모두 충족해야 한다.

1. V1이 `30/10/10/5/5`와 사건 0건으로 `GO`이며 근거가 유효하다.
2. 하나의 고객·문제·웨지와 제외 주장이 고정돼 있다.
3. A/B 두 안은 허용된 세 카피 필드 외에 동일하다.
4. 실제 표본 크기와 판정 방법이 결과 확인 전에 동결됐다.
5. 오퍼의 범위·가격·예약금·환불·제공 조건과 검토 ID가 완결됐다.
6. 공급자·국외 이전·접근·보존·삭제·사건 경로가 승인됐다.
7. LP-001~018의 실제 실행 방법과 결과가 기록됐다.
8. 14일 종료·환불창·소유자 자체 재집계 시점을 서로 바꿔 쓰지 않는다.
9. 랜딩 GO가 V2-B 컨시어지 검증만 허용하고 제품 구현은 허용하지 않는다고 결정문에 적는다.

현재 V1 GO, 선택 웨지, 실제 오퍼, 공급자, 채널, 예산과 표본 계산이 없으므로 실행 상태는 `BLOCKED`다.
