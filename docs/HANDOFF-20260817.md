## 최우선 과제 — `develop`이 CI를 통과하지 못한다

### 증상

`develop`에서 분기한 브랜치의 PR은 **`npm ci` 단계에서 실패**한다.

```text

npm error Missing: @emnapi/core@1.11.3 from lock file
```

실측: `git show origin/develop:landing/package-lock.json | grep -c '"node_modules/@emnapi'` → **1** (정상은 3)

### 원인

lock 파일 복구(TASK-0001 WF-08)가 **`task/TASK-0001-landing-public-gate`에만 있고 `develop`에 없다.** TASK-0001이 미병합이라 그 안의 모든 수정이 갇혀 있다.

### 해결 순서

1. **TASK-0001의 WF-05·WF-06을 별도 TASK로 분리**한다. 두 Workflow는 배포 보류로 `Blocked`이며, 이 때문에 TASK-0001이 `Done`이 되지 못하고 있다
2. TASK-0001을 `Done`으로 만들고 **Task PR → `develop`** 병합
3. PR #11(TASK-0003)에 `develop`을 병합해 최신화 → CI 재실행 → 통과 확인 후 병합

**2번에서 `landing/app/page.tsx` 충돌이 예상된다.** TASK-0001(WF-03의 폼 문구)과 TASK-0003(카피 재정리)이 같은 파일을 건드렸다. 양쪽 의도를 모두 보존해 해결한다.

## 이 세션에서 확인한 사실 — 문서만 봤으면 몰랐을 것들

전부 출처와 함께 `docs/verification/fitpulse-landing-platform-data-handling-20260817.md`에 있다.

| 사실 | 영향 |
|---|---|
| 이 랜딩은 **ChatGPT Sites 배포**이고 D1도 플랫폼이 프로비저닝한다 | D1 직접 생성 계획 폐기. 플레이스홀더 `database_id`는 결함이 아니라 의도된 설계 |
| **데이터 레지던시 미지원** (D1/R2 저장·로그 전부) | 저장 국가 특정 불가 → 안내에 명시 |
| **예약 작업(cron) 미지원** | 보존 정책이 안 돌 뻔함 → 삭제 경로 3개로 대체(WF-09) |
| **삭제 후 플랫폼 내부 최대 30일 잔존** | "즉시 삭제" 문구 정정 |
| 소유자가 Controller, OpenAI가 Processor | 개인정보 책임이 소유자에게 있음 |
| 재위탁 사업자가 페이지에 **보안·안전 분류기 실행** | 안내에 명시 |
| Sites는 유료 플랜 번들 — **Cloudflare 종량 비용은 부담하지 않음** | WF-05의 비용 위험 전제 폐기 |
| SES 서울 리전(`ap-northeast-2`) 지원 | 발송 수탁자를 국내에 둘 수 있음 |
| **SES 샌드박스는 수신자 사전 검증 필요** | 프로덕션 액세스 승인이 실제 발송의 선행 조건 |

### 근거의 한계

레지던시·cron·비용 사실은 **2차 자료가 인용한 OpenAI 문서 문구**에 근거한다. `help.openai.com`과 `openai.com/policies`가 **HTTP 403**을 반환해 원문을 대조하지 못했다. 공개 판정 전 원문 확인이 필요하다.

## 이 세션에서 밟은 함정 — 반복하지 말 것

| 함정 | 교훈 |
|---|---|
| `wrangler d1 info` 결과만 보고 D1을 생성했다가 삭제 | **인프라 판단 전에 `vite.config.ts`·빌드 플러그인·호스팅 설정을 먼저 읽는다** |
| Workflow 병합 전에 Task Branch를 수정해 충돌 2회 | **Workflow PR을 먼저 병합한 뒤 Task Branch를 갱신한다** |
| `landing/.dev.vars`가 있으면 `--var` 주입이 무효화된다 | 로컬 QA는 `--var`를 쓰고 `.dev.vars`를 두지 않는다. 원인은 규명하지 못했다 |
| `--env-file`은 Worker `env` 바인딩에 반영되지 않는다 | `package.json`의 `start`를 원복했다 |
| 테스트 개수·WF 상태를 잘못 기록했다가 정정 | 검증 기록은 실제 출력으로 대조한다 |
