**계획 산출물을 스킬 기본 경로에 두지 않았다.** 브레인스토밍·writing-plans 스킬은 산출물을 `docs/superpowers/` 아래에 두라고 기본 지정하나 `CLAUDE.md` 1절(규칙 우선순위)에 따라 저장소 규칙이 앞선다. 설계는 `docs/plans/`, 구현 계획은 TASK/Workflow 문서다.

**통합 브랜치를 고치는 변경은 TASK 마감 조건에 묶지 않는다.**

WF-08의 lock 복구는 "현재 TASK와 무관한 결함" 기준으로 별도 Workflow로 분리한 것까진 옳았다. 그러나 Task Branch 안에 두었기 때문에 TASK 마감 조건에 묶였고, 배포를 기다리는 문서 작업 2개가 이미 끝난 코드 수정의 통합을 막았다. **통합 브랜치의 CI를 복구하는 성격의 변경은 처음부터 독립 TASK로 만들어 `develop`에 직행시켰어야 했다.**
