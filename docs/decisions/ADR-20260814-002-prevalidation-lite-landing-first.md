# ADR-20260814-002: 랜딩 우선 사전 검증

Status: ACCEPTED — OWNER-DIRECTED

Decision date: 2026-08-14

Applies to: 제품·서비스 출시 전 랜딩과 초기 수요 데이터 수집

## 결정

현재 단계를 `PREVALIDATION_LITE`로 전환한다. 지금의 우선순위는 문서 게이트를 완성하는 일이 아니라 다음 두 가지를 실제로 만드는 것이다.

1. 한 가지 고객 문제를 설명하는 모바일 우선 랜딩페이지
2. 대기자와 비민감 수요 신호를 분리해 수집하는 최소 데이터 흐름

기존 B-00~B-05 기록과 단계별 게이트 문서는 폐기하지 않지만, 현재 랜딩 구현을 막는 선행 승인으로 사용하지 않는다. `AUTH-V0-B00-20260814-002`와 `ROLE-V0-B01-20260814-001`은 이력 참조로 유지하며 추가 서명·대조 작업을 지금 요구하지 않는다.

## 지금 진행하는 범위

- 브랜드 확정 전의 임시 제품명으로 랜딩 디자인·구현·QA
- 이메일 대기자 등록
- 운동 빈도, 사용 기기, 현재 기록 방식, 다음 중량 결정 방식처럼 건강정보가 아닌 고정 선택형 질문
- 개인식별자를 포함하지 않는 방문·CTA·제출 이벤트 측정
- 실제 공급자와 고지문을 확인한 뒤 랜딩 공개 및 소규모 채널 실험
- 소유자가 정한 전체 검증 예산 상한 500,000원 안의 집행

## 지금 제외하는 범위

- 통증, 부상, 수술, 수면, 심박, 산소포화도 등 건강·의료 관련 응답 수집
- 결제, 예약금, 계약 또는 유료 약정
- 개인별 운동 루틴·중량·회복 추천
- 회원 계정, 인증, Health Connect 연동
- 앱스토어 출시 또는 정식 서비스 제공

## 최소 운영 기준

아래 기준만 랜딩 공개 전 필수로 확인한다.

- 아직 개발 전 검증 단계임을 숨기지 않는다.
- 이메일 저장소와 행동 이벤트 저장소를 논리적으로 분리한다.
- URL, 분석 이벤트, 애플리케이션 로그에 이메일을 넣지 않는다.
- 실제 저장·분석 공급자, 수집 항목, 목적, 보유 기간, 삭제 요청 방법을 공개 시점의 개인정보 안내에 적는다.
- 동의하지 않거나 철회한 사람의 등록·삭제 흐름을 실제로 시험한다.
- 랜딩 반응은 수요 신호로만 보고 제품 적합성·결제 의사·법적 적합성으로 과장하지 않는다.

## 정식 문서 체계 재개 조건

다음 중 하나를 시작하기 전에 당시의 실제 공급자·계약·제품 흐름을 기준으로 운영, 개인정보, 보안, 예산과 출시 문서를 다시 작성하고 검토한다.

- 결제 또는 환불이 발생하는 오퍼
- 건강·의료·웨어러블 데이터 수집
- 개인화된 운동 조정이나 안전 관련 안내
- 회원 계정과 인증
- 공개 베타, 앱스토어 제출 또는 정식 서비스 운영

이 결정은 위 의무를 면제하지 않는다. 아직 존재하지 않는 서비스 운영을 가정해 문서를 미리 확정하지 않겠다는 범위 조정이다.

## 기존 문서와의 관계

- [개인사업자 1인 자체 검토 거버넌스](./ADR-20260814-001-sole-proprietor-self-review-governance.md)는 책임 주체 기록으로 유지한다.
- [V2 랜딩 수요 실험 계획](../plans/fitpulse-v2-landing-demand-experiment-plan-20260814.md)의 V1 선행 게이트와 유료 약정 절차는 현재 단계에서 적용하지 않고, 정식 서비스 전환 시 참고한다.
- 현재 실행 기준은 [랜딩·데이터 검증 실행 계획](../plans/fitpulse-landing-data-validation-execution-plan-20260814.md)이다.
