## 1. 프로젝트 목표 및 범위 (Scope)

### 1.1 목표

| # | 목표 | 성공 기준 |
|---|------|-----------|
| G1 | 오프라인에서도 유실 없는 운동 기록 | 실기기 검증 시 기록 유실 0건 |
| G2 | Health Connect 기반 건강 데이터 자동 수집 | 반복 동기화 시 중복 0건, 삭제 반영 100% |
| G3 | 안전성이 검증된 AI 루틴 추천 | DB 미존재 운동 0%, 금기 운동 포함 0% |
| G4 | 앱 스토어 심사 통과 가능한 개인정보 처리 | 동의 5종 분리, 30일 유예 삭제, 데이터 내보내기 |
| G5 | 정의된 SLA 충족 | 세트 기록 P95 < 200ms 등 8개 API 기준 충족 |

### 1.2 In-Scope (MVP 14주)

| 영역 | 포함 기능 |
|------|-----------|
| 인증 | 이메일 + Google PKCE, Rotational Refresh, Device Session(5대 상한), 동의 관리 |
| 사용자 | 프로필, 신체 정보, 운동 목표(부상 포함), 계정 삭제(30일 유예) |
| 운동 라이브러리 | 검색·분류·상세·커스텀 등록 (100+ 시딩) |
| 루틴 | 생성·수정·복사·주간 배정, 버전 관리 |
| 운동 기록 | 세션·운동·세트, 타이머, RPE, Operation Queue, 멱등성, 파생값 재계산 |
| 분석 | 볼륨 추이, 1RM 추이, 부위별 빈도, 캘린더(잔디), 스트릭 |
| 건강 지표 | 체성분 수동 입력 + Android Health Connect (Change Token + BG Observer) |
| AI | 검증형 루틴 추천 (비동기 Job + Fallback + 3단계 매핑 + 안전성 검증) |

> **v5.0 주의**: 위 표는 원 계획서 v4.0의 MVP 정의를 그대로 유지한 것입니다. 아래 1.2-1의 커뮤니티·관리자는 MVP 14주 **이후의 확장 트랙(A1~A4)** 으로 분리 편성하여, 원 MVP 일정과 범위를 침범하지 않습니다.

### 1.2-1 확장 트랙 (A1~A4, 4주) ★ v5.0

원 계획서 11장의 루틴 API(`GET public`, `POST like/copy`)와 기술 스택의 `Redis: 랭킹`, 후속 백로그의 `React 관리자` 항목을 **누락 없이 이행**하기 위한 트랙입니다.

| 트랙 | 주차 | 범위 | 근거 |
|------|------|------|------|
| **A1** | 15주차 | 커뮤니티 — 루틴 공개·심사 요청, 공개 목록, 좋아요, 랭킹(Redis ZSET), 신고 | CR-013 (원 계획서 11장·2장 복원) |
| **A2** | 16주차 | 관리자 기반 — `admins` 계정 체계, RBAC 5역할·27권한, TOTP 2FA, 세션 정책, 감사 로그 | CR-014 |
| **A3** | 17주차 | 관리자 운영 — 회원 관리, 콘텐츠 관리, 공지, 신고·제재, 점검 모드 | CR-014 |
| **A4** | 18주차 | 관리자 AI·통계 — 프롬프트 운영, 매핑 검수, 비용·킬스위치, 통계, 2인 승인, 부하·보안 검증 | CR-014 |
| **V1.1** | 별도 4주 | React 19 관리자 웹 콘솔 UI | 원 계획서 후속 백로그 |

### 1.3 Out-of-Scope (후속 백로그)

| 버전 | 항목 |
|------|------|
| V1.1 | iOS HealthKit, FCM 푸시, **React 관리자 웹 UI** (백엔드 API는 A2~A4에서 선구현) |
| V1.2 | 식단 기록, 영양소 분석 |
| V2 | Vision(자세 분석), 트레이너 매칭, 뱃지 |
| V2+ | 소셜 피드, 챌린지 (**랭킹은 A1에서 선구현** — 원 계획서 기술 스택의 `Redis: 랭킹` 반영) |

### 1.4 제외 명시 (오해 방지)

- 의료적 진단·처방 기능 없음 (모든 AI 출력은 "참고용 피트니스 인사이트")
- 혈압·혈당 등 민감 건강 데이터 수집 안 함
- 결제/구독 기능 MVP 제외
- 커뮤니티·관리자는 MVP(W1~W14) 제외, 확장 트랙(A1~A4)에서 수행
- 사용자 간 팔로우·댓글·DM은 전 범위 제외 (V2+ 소셜 피드에서 재검토)

> **일정 원칙**: A1~A4는 MVP(W1~W14) 완료 후 착수합니다. MVP 일정이 지연되면 A 트랙이 밀릴 뿐 MVP 범위는 축소하지 않습니다. 반대로 커뮤니티·관리자를 MVP 안으로 당기는 요청은 CR 절차로만 검토합니다.

> **버퍼 정책**: 각 주차 산정에는 실작업 4일 + 버퍼 1일을 포함합니다. W14는 전체가 안정화 버퍼 역할을 겸하며, M3·M4 지연 시 W7(분석)을 W11로 이동시켜 흡수합니다.
