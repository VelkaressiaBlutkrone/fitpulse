## 일정 구조

```
[MVP] W1 ─────────────────────────── W14        (원 계획서 범위, 변경 없음)
                                       │
[확장]                                 └─ A1  A2  A3  A4      (4주)
                                          커뮤 관리 관리 관리
                                          니티  기반 운영 AI·통계
                                                                │
[V1.1]                                                          └─ React 관리자 웹 (4주)
```

**원칙**: A 트랙은 MVP 완료 후 착수합니다. MVP가 지연되면 A 트랙이 밀릴 뿐, **MVP 범위는 축소하지 않습니다.** A 트랙은 MVP와 독립적으로 승인·보류할 수 있습니다.

## 관리자 기능 요약 (CR-014)

| 영역 | 요구사항 | 핵심 |
|------|----------|------|
| 계정·권한 | FR-901~910 | `admins` 별도 테이블, RBAC 5역할×27권한, TOTP 2FA, IP 허용, 30분 세션, 초대 가입 |
| 감사 | FR-911~916 | 쓰기 + **민감 조회까지** 100% 기록, 수정·삭제 불가, 3년 보관, 이상 행위 알림 |
| 회원 | FR-921~929 | 검색·상세, PII 마스킹/사유부 해제, 정지·강제로그아웃, **데이터 수정 불가** |
| 콘텐츠 | FR-931~939 | 운동 CRUD·CSV 일괄, 공개 루틴 심사, 시스템 루틴, 공지, 점검 모드 |
| 신고·제재 | FR-941~945 | 신고 큐, 제재 5종, 이력, 이의제기 재심 |
| AI 운영 | FR-951~958 | 프롬프트 dry-run·활성화·**무배포 롤백**, 매핑 검수, 비용, 한도, 킬스위치 |
| 통계·도구 | FR-961~968 | DAU/리텐션, CSV, 배치 수동 실행, 런타임 설정, **2인 승인**, React 콘솔(V1.1) |

**설계상 관리자가 할 수 없는 일** — 회원의 운동·건강 데이터 수정(FR-929), 감사 로그 수정·삭제(FR-912), 관리자 계정 물리 삭제(D-18), 본인 요청 자가 승인(FR-967).

| 명명 규칙 | `FitPulse_[문서유형]_v[버전]_[YYYYMMDD].md` |
| 버전 규칙 | 내용 보완 = 마이너, 구조·범위 변경 = 메이저 |
